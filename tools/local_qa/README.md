# 本地文件問答工具（local_qa）

> 這是在 DHC CLI 主機上的試作版。正式位置是 srv-db：同一套檢索＋作答邏輯正移植成 srv-db 代理程式 v3 的 `doc-qa` 動作（`Harness優化\deploy_docqa_v3_20260930\`），公司內部文件請在 srv-db 上建索引，不要搬到這台。

這個工具讓你把一整批公司內部文件（規章、SOP、備忘錄…）丟給一個「完全在這台機器上跑」的小型 AI，用中文問問題、拿到附出處的答案。

**沒有任何資料會離開這台機器。** 不連雲端、不呼叫任何外部 API，只用本機的三個小模型（檢索、排序、回答），全部跑在 127.0.0.1（只有你自己的電腦能連得到）。

## 使用者怎麼用（透過聊天）

你不用自己打指令。跟平常聊天一樣說：

- 「用本地問答問：錯帳部位最晚要在什麼時候之前了結？」
- 「幫我把 X 資料夾的文件加進本地問答的索引」

小幫手會幫你在背景跑對應的 `node qa.cjs ask ...` / `node qa.cjs ingest ...` 指令，把結果貼回聊天視窗。

## 這工具在做什麼（技術上）

1. 你把文件（.md / .txt / .docx）放進一個資料夾，跑 `ingest` 建索引：文件先切成小段（chunk），每段做「向量化」存起來。
2. 你問問題時：先用向量比對抓出最相關的 30 段，再用第二個小模型把這 30 段重新排序，取最相關的前 6 段。
3. 把這 6 段連同問題交給第三個小模型（Qwen3.5-4B）生成繁體中文答案，每個事實後面附 `[文件段落編號]` 出處，最後一行標明 `STATUS: ANSWER / NO_INFO / CONFLICT / DENIED`。
4. 如果格式不對（例如漏了 STATUS 行、引用了不存在的段落），工具會自動請模型重寫一次；還是不對就照原樣印出來，你自己判斷。
   - 2026-09-30 晚上調整（和 srv-db v3.1 相同）：回答字數上限 512 → 1024（原本近半數重寫是長答案被截斷）；答案完整只漏 STATUS 行時只補問一行，不整題重寫；常見引用寫法錯誤直接用程式修（`lib/format_fix.cjs`，例如 `（X#01）`、`[MAP:X#01]`、`[X#01, Y#02]`）；「文件裡找不到」的答案不再強制附引用。提示詞第一行從「助理」改成「助手」，和 srv-db 上的 C# 版逐字一致（`gemma-offline\agent-channel\check-contract-parity.cjs`）。
5. 逐字核對（`lib/grounding.cjs`，2026-09-30 下午加）：答案裡的日期（含民國日期）、時間、帶單位的數字、代碼／表名／檔名／路徑、條號，要在引用的段落找得到。找不到會印 `⚠ 核對：…`（檢索到的段落都沒有，多半是推算或模型自己加的）；只在其他段落找得到會印 `△ 核對：…`（出處可能引錯）。它只看寫法有沒有出處，看不出版本選錯、引錯頁或意思錯；12 小時制時間（「下午 3:30」對原文「15:30」）會誤標。74 份已跑答案的評估：通過的 39 份 0 份被標 ⚠，嚴重錯 7 份抓到 3 份（`node grounding_eval.cjs`）。srv-db 版 `Grounding.cs` 用同一套規則，回傳欄位 `unsupported`／`cited_elsewhere`。

## 指令（給要手動操作的人）

在 `tools/local_qa` 資料夾底下（`cmd.exe` 或 PowerShell 都可以，指令是給 Node.js 的）：

```
node qa.cjs serve                       # 啟動三個本地模型（背景執行，約 1-3 分鐘）
node qa.cjs status                      # 看模型是否還活著
node qa.cjs ingest <文件資料夾> --name <索引名>   # 把一批文件建成索引
node qa.cjs ask "你的問題" --index <索引名>       # 問問題
node qa.cjs stop                        # 關掉三個本地模型，釋放記憶體
```

`ask` 如果發現模型還沒啟動，會自動幫你啟動（第一次會多等 1-2 分鐘）。

範例：

```
node qa.cjs ingest "C:\我的文件\規章" --name mydocs
node qa.cjs ask "出差可以報帳到多少？" --index mydocs
node qa.cjs stop
```

`ask` 額外可用的參數：
- `--json`：印出機器可讀的 JSON（給程式呼叫用，不是給人看的）。
- `--history '[{"role":"user","content":"..."},{"role":"assistant","content":"..."}]'`：多輪對話時，把之前的對話帶進去。
- `--user '{"role":"自營部交易員"}'`：帶入提問人的身份/情境（目前只影響提示語，不做權限管制）。
- `--as-of 2026-09-30`：指定「以哪一天的日期」判斷文件是否已生效/已廢止；不給就用今天。

## 加入你自己的文件

1. 把 `.md`、`.txt`、`.docx` 檔案放進任一個資料夾（可以有子資料夾）。
2. 跑 `node qa.cjs ingest <那個資料夾> --name <你取的索引名字>`。
3. 之後問問題時加 `--index <索引名字>`。

檔名叫 `README.md`、`INDEX.md`、`CORPUS.md`（不分大小寫）的檔案會被跳過，因為那通常是目錄說明而不是內容。

如果文件內容有更新，重新跑一次 `ingest`（同樣的資料夾＋索引名）即可；工具會檢查檔案有沒有變，沒變就不會重算，省時間。要強制整批重建可以加 `--force`。

## 已知限制

- **不支援 PDF**、Word 舊格式 `.doc`（只支援新版 `.docx`）、圖片、掃描檔。
- 4B 的小模型偶爾會答錯或漏答，**永遠要自己核對「來源」欄位列出的段落**，不要盲目相信答案。
- 這是單機小模型，遇到很細節、需要跨很多文件比對的問題，品質會比雲端大模型差。
- 一次只能問一個問題（無記憶），要延續對話請用 `--history` 手動帶入之前的對話。
- 每次啟動 `serve` 大約吃掉 7 GB 記憶體（三個模型加起來，2026-09-30 實測 4.9＋1.0＋1.4 GB），問完事情記得 `node qa.cjs stop` 把它們關掉，不然會一直占著記憶體；記憶體吃緊時 Windows 會把分頁檔撐大、C 槽空間跟著變少。

## 重要安全提醒：不要用 DHC CLI 附件上傳機密文件

**如果你是透過 Discord／DHC CLI 聊天視窗操作，請不要把機密文件當附件傳給小幫手去做本地問答的索引。** 附件會先存到一個「公開下載資料夾」，任何人只要有連結就看得到，這樣機密文件就外流了。

正確做法：把文件直接放在這台電腦本機的某個資料夾（例如 `C:\我的文件\規章`），然後跟小幫手說「幫我把這個資料夾的文件加進本地問答」，讓它在本機直接讀取、不經過任何上傳。

## 停止服務 / 確認沒有殘留

```
node qa.cjs stop
node qa.cjs status
```

`stop` 只會關掉本工具自己啟動、記在 `state\servers.json` 裡的程序，不會動到其他跟這個工具無關的東西。如果你想再三確認沒有殘留，可以在命令列跑 `tasklist /FI "IMAGENAME eq llama-server.exe"` 檢查還有沒有本工具的模型在跑。
