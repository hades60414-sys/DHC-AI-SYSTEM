# 閘門在目標架構裡的位置（2026-09-30）

目標架構：**DHC CLI（雲端 Claude）是大腦與操作介面**，決定要做什麼；**srv-db 上的開源模型與代理程式是手腳**，只執行派工通道送來的白名單動作，並負責文件問答。本地模型不做判斷。

在這個架構裡，`gate.cjs` 那套「解析任意指令與 SQL、比對白話核准單」的規則大多用不到：srv-db 本來就不接受任意指令。真正需要的是 srv-db 代理程式端的三道檢查。

## srv-db 端的三道檢查

| 檢查 | 現況（agent v2／v3） | 還缺什麼 |
|---|---|---|
| 1. 動作在白名單 | 已有：`AgentCore.ActionAllowed`（health、model-info、reason、reason-json、唯讀檔案工具，v3 加 doc-qa；沒有 SQL、沒有寫檔） | 新增動作時一律加進白名單並寫測試 |
| 2. 參數格式正確 | 已有：唯讀檔案工具只收 `path`／`pattern` 並限制在 readonly-roots；doc-qa 只收 `question`／`index`／`as_of` | 每個新動作都要有固定欄位、型別、長度與範圍檢查，多一個欄位就拒絕 |
| 3. 需要授權的有對上授權 | 派工本身已簽章加密、有序號與 15 分鐘時效，能確認「是 DHC CLI 送的」 | **目前沒有任何寫入動作，所以還不需要。** 將來加寫入動作（刪檔、覆寫、派排程…）時才做，規則見下 |

## 將來加入寫入動作時的授權規則（草案）

- 寫入動作的參數必須是固定結構（例如 `{"path":…,"older_than_days":90,"pattern":"*.csv"}`），不接受任意指令或任意 SQL。
- 每次寫入要附一張**使用者核准的授權單**：由使用者在 DHC CLI 確認後產生、以控制端金鑰簽章，內容就是這一次的動作名稱與完整參數、有效時間、主機。
- 代理程式執行前逐欄比對「派工的動作與參數」和「授權單上的動作與參數」完全相同、在有效時間內、主機是自己；任何一項不符就拒絕並回報。
- 授權單只能用一次（記在代理程式的日誌裡），避免重送。
- 執行前先做一次試跑（dry run）回報影響範圍，比對核准時的數量；數量變了就拒絕。

這樣授權比對是「結構相等」，不需要解析白話或指令字串，`gate.cjs` 三輪攻擊找到的那些繞過方式在這裡不存在。

## gate.cjs 之後的角色

- 保留當 DHC CLI 端的**事前提醒**：大腦下指令前先跑一次，看有沒有漏了授權、備份、重複派工這類事；結果只供參考，不當最後防線。
- 攻擊測試（test_adversarial*.cjs）留作紀錄：說明為什麼執行端不能接受任意指令。
