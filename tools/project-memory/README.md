# 專案記憶

從 DHC CLI / Claude Code 的工作 session 蒸餾出來的**專案知識卡**。以專案為身分，不以人為身分：卡片記的是「這個東西是什麼、規格、怎麼做、踩過什麼坑」，不記「誰做的」。

用途：
- 在任何工作區開工時，Claude 先看 `INDEX.md` 找相關專案卡，接續既有規格，不重新摸索。
- 交接時，新同事直接讀對應的專案卡。

## 怎麼用（同事）
- 什麼都不用做。在自己的工作區跟 Claude 講要做的事，它會自己查卡。
- 發現卡片寫錯：直接跟 Claude 說「專案卡 X 的某某不對，應該是…」，它會改卡並在「決策紀錄」留一筆。

## 怎麼更新（管理者）
在 DHC CLI 任一對話說「**蒸餾專案記憶**」即可（流程在 `DISTILL.md`）。工具在 `Harness優化\project-memory\`：
- `node pm.cjs extract`：把新的／有增長的 session 轉成去敏摘要（`digests\`，暫存）
- `node pm.cjs done`：蒸餾完標記、清掉暫存摘要
- `node pm.cjs check`：掃卡片裡有沒有密碼、email、身分證號、大額數字、人名

## 卡片規則（寫卡的人／AI 都要守）
1. **只寫角色，不寫人名**：寫「部長」「業務管理部」「交易員」，不寫姓名。工作區資料夾名只能出現在路徑裡。
2. **不寫數值資料**：部位、損益、金額、帳號、客戶資訊一律不進卡。規格可以寫「欄位 X = 部位 × 價格」，但不能寫實際數字。
3. **不寫密碼與連線帳密**：只寫「連線設定在 config.php」這類位置。
4. **每條規格都要有來源**：在句尾標 `〔s:xxxxxxxx 09-21〕`（session 前 8 碼與日期），讓人可以回查。
5. **不確定就標記**：推論出來、還沒被使用者確認的內容加 `（未確認）`。
6. **新的蓋舊的**：規格有變時直接改正文，舊做法移到「決策紀錄」並寫原因。
