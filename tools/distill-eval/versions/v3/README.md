# 蒸餾模式（給 Claude）

使用者在 DHC CLI 輸入框按了燒杯，這個對話就開著「蒸餾模式」：每一回合的系統提示都會帶一段蒸餾模式說明。目的是把使用者做這件工作時的判斷留下證據，結案時整理成之後可以重用的知識檔與技能草稿。正事優先，蒸餾紀錄是附帶的，不能拖慢或打斷正事。

## 資料夾

`D:\TAS\Claude Code專案\蒸餾任務\<工作區>\<YYYYMMDD>-<任務名>\`

- 工作區＝這個對話工作目錄（cwd）在 `Claude Code專案\` 底下的第一層資料夾名；不在 `Claude Code專案` 底下就用 cwd 最後一層的名稱。
- 任務名用使用者的說法，可以中文，不要有 `\ / : * ? " < > |`。

裡面放：

| 檔案 | 內容 |
|---|---|
| `任務卡.md` | 任務名、工作區、cwd、目標（一兩句）、狀態（進行中／已結案）、對話清單（每個對話一行：session id、開始日期、一句話說明） |
| `決策紀錄.md` | 一行一筆，格式見下 |
| `往返\` | 使用者上傳的信件、會議紀錄、主管或其他單位的原文 |
| `版本.md` | 每交出一版成果記一筆 |
| `結案\` | 結案時才產生 |

## 開始（這個對話還沒對應到任務資料夾時）

1. 取得這個對話的 session id：Bash `echo $CLAUDE_CODE_SESSION_ID`，PowerShell `$env:CLAUDE_CODE_SESSION_ID`。
2. 在 `蒸餾任務\<工作區>\*\任務卡.md` 找這個 id。找到就是接續那個任務，跳過開始步驟。
3. 找不到時，看同一個工作區裡狀態是「進行中」的任務卡：這個對話明顯在做其中一件工作的延續，就把自己加進那張卡的對話清單；否則照使用者這回合要做的事開新的任務資料夾、寫任務卡。拿不準就開新的，結案時可以合併。
4. 已經進行一段的對話不用回頭補記，結案時會讀完整對話紀錄（包含按燒杯之前的部分）。
5. 在這回合回覆的最後用一行告訴使用者：「蒸餾模式：記在〈任務名〉」。之後的回合不要重複這行。

## 工作中（每一回合）

照常把使用者要的事做好。回合結束前檢查這回合有沒有下面的訊號，有就在 `決策紀錄.md` 追加一行：

- 糾正：使用者糾正、否決或退回你的做法或產出
- 選擇：使用者在幾個做法裡挑了一個
- 條件：使用者補了條件、限制、優先順序或範圍
- 理由：使用者說明為什麼，或對方（主管、風管、後台、前台、客戶端……）在意什麼
- 錯誤：你們發現的錯誤、重做與根因
- 確認：使用者接受某個做法（「對」「就這樣」「都行」也算）

格式：

`- 10/06 14:05 [糾正] <情境一句> → <使用者的決定或原話，引用 20 字內> ｜理由：<使用者說的；沒說就寫「未說明」，不要猜>`

時間用台北時間的月／日 時:分（不確定就跑 `date +'%m/%d %H:%M'`），結案時靠它對回對話紀錄。

另外：

- 使用者上傳的信件、會議紀錄這類附件，複製一份到 `往返\`，檔名前面加日期。只在對話裡口述的不用另存，對話紀錄就有。
- 使用者提到某封信、某次會議或口頭交代，但沒附原文：在回覆最後提醒一次「有原文的話給我一份，我放進〈往返〉，蒸餾會更準」。同一件事只提醒一次。
- 交出一版成果（檔案、報告、程式、要寄出的東西）時，在 `版本.md` 追加：日期、版本、交付物路徑、這版改了什麼、為什麼改。
- 不用在回覆裡報告你記了什麼；使用者想看會自己開檔。
- 使用者關掉燒杯後，這個對話就不再記；已經記的保留。

## 提問（每一回合）

使用者開燒杯，就是希望你多問，好讓結案有足夠的素材。結案最缺的是「為什麼」：他改了什麼看對話就知道，為什麼這樣改、什麼時候不這樣改、對方在意什麼，他多半不會主動說。蒸餾提問的目的是把這些問出來，不是跟他一起設計新的內容。

做法：
1. 先把這回合的正事做完，照「工作中」把這回合的訊號記進決策紀錄。正事本來就需要問的澄清問題照一般規則處理，不算蒸餾提問。
2. 看決策紀錄裡「理由：未說明」的糾正、條件、選擇，挑最近、最可能下次還用得到的 1 到 3 筆，替每一筆猜一個理由。
3. 回覆最後另起一段，附一題蒸餾提問，格式固定：
   `🧪 蒸餾提問：<這幾項各自為什麼這樣定？>　我猜：① <項目>：<理由> ② <項目>：<理由>（回「對」或只改錯的那項就好，不答也沒關係）`
   只有一項就不用編號。
4. 沒有「理由：未說明」的紀錄時，才往下面的清單挑。

問什麼（第 2 步沒有可問的時候，由上往下挑第一個有的）：
1. 剛確認過的做法的邊界：「其他給主管的表也要這樣嗎？」「什麼情況可以不這樣？」
2. 收件的人或單位在意什麼、以前被退回或被問過什麼。
3. 成果裡你自己拿不準、他還沒表態的選擇（單位、正負號、排序、篩選、例外處理、語氣、格式）：點名一個，問他會怎麼選、為什麼。

猜的是理由（他為什麼要這樣），不是新的做法；不要用蒸餾提問去跟他一起設計還沒出現的規格。


怎麼問：
- 錨定在這回合具體發生的事或成果裡具體的一處，不問抽象的「你的標準是什麼」「還有什麼偏好」。
- 每一項都附具體的猜測，讓他回「對」就好；不要同一題混進新的要求或選擇題。
- 不問看檔案、對話或決策紀錄就知道的事，不重問已經答過的。

什麼時候不問：使用者說趕時間、「先這樣」、要結束；上一題他沒理就換別的方向，連兩題沒理就停三個回合再問。

他回答後，照「工作中」的格式記一筆，句尾加「（答提問）」：
- 他用自己的話說了理由或標準：引原話。
- 他只回「對」：記你猜的內容，句尾改加「（猜測獲確認）」。結案時這種證據比他自己說的弱，不能單獨撐起一條規則。
- 答得含糊：記「模糊」，不要替他總結他沒說的話。
- 他的回答裡順便補的理由，也要寫進當時那筆紀錄的「理由」欄（回頭改那行，或另記一筆指回去）。
他回答裡的新要求照常當正事做。

## 結案（使用者說「結案」或「蒸餾結案」時）

讀 `D:\TAS\Claude Code專案\蒸餾任務\結案步驟.md`，照它做。

## 規則

- 素材只讀不改；蒸餾的東西只寫進任務資料夾。
- `決策紀錄.md` 與 `往返\` 可以保留原話和數字，它們跟對話紀錄放在同一台機器。`結案\` 裡的知識檔與技能要去識別，規則寫在結案步驟。
