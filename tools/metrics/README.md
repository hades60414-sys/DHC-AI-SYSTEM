# 決策負擔量測（2026-11-03）

用途：看 TAS 的自主機制有沒有真的少耗使用者的決策力，而不只是 regex 有命中。來自 11-03 觀察者的量測設計，使用者回「都做」同意。

每週一 09:10 排程 `TAS-Metrics-Weekly`（Interactive，要使用者登入中）跑 `weekly.cmd` → `weekly.cjs`，結果加一列到 `history.tsv`，輸出與錯誤在 `weekly.log`。

| 指標 | 怎麼算 | 方向 |
|---|---|---|
| 只回一句好 | `assent-baseline.cjs`：Harness優化 使用者訊息裡「OK／好／都做」這類短回覆的比例（規則事先固定，不放寬）。對照點是 10-28 turn-end-guard B 類上線 | 越低越好：AI 少問了沒資訊量的問題 |
| 逐項回答 | 同上，「1可以 2…」這類帶資訊的回答 | 不該掉：有價值的提問沒被一起壓掉 |
| 不返工收下率 | `rw-data.cjs` 抽出最近 14 天「AI 宣稱完成 → 同對話使用者下一則」，`rw-judge.cjs` 交給 sonnet 判 A 返工／C 小調整／B 其他 | 越高越好 |

## 準確度（11-03 驗證）
- 關鍵字判返工不能用：算出收下率 99%，人工抽 40 則，4 則真返工只抓到 1 則。
- haiku 判讀：和人工三類一致 75%，返工類只抓到一半，不採用。
- sonnet＋現在的提示：和人工一致 88–93%。返工類仍有少量漏判（例如看圖的糾正），數字當趨勢看，不當精確值。

## 基準（11-03）
- 只回一句好：hook 上線前 2.0%（24/1214），上線後 0.6～0.8%。逐項回答 0.8% → 1.4%。
- 不返工收下率 84–89%，不用調整就收下約 73–75%（149 次宣稱完成）。
- 同一份資料連跑兩次（手動 83.9%、排程 86.6%）：模型判讀本身有約 ±3 個百分點的浮動，週與週之間差不到 5 個百分點不算變化。

## 手動
- `node weekly.cjs`（約 5 分鐘、用 sonnet 8 次）；`node weekly.cjs --no-judge` 只跑不花額度的那項。
- 停用：`schtasks /change /tn TAS-Metrics-Weekly /disable`；移除：`schtasks /delete /tn TAS-Metrics-Weekly /f`。
