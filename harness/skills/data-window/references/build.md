# 替一台機器的資料庫建窗口：施工步驟

目標是做出跟 `example-DATA_API.md` 同一種形狀的窗口，契約見 `contract.md`。每一步完成都要先驗證，再進下一步。

## 0. 先問人（得到回答前不連資料庫）

- 要開放哪個庫、哪些表或檢視。部位、損益、委託、客戶類資料一律不放。
- 唯讀帳號：請 DBA 開只有讀取權限的帳號（例如 db_datareader），密碼只放在環境變數。
- 誰會來撈：只有本機、區網，還是要像範本一樣用固定網址對外。三種的開放方式不同，見第 6 步。

## 1. 盤點（只讀不改）

- 環境：資料庫引擎與版本、Node 版本、npm 能不能安裝套件、作業系統。
- 每張候選表：列數、主鍵（沒有主鍵就找出能唯一識別一列的欄位組合）、日期欄的範圍和格式、各欄的空值率、單位。
- 已知的髒資料：重複的鍵、日期戳錯誤、單位混用（例如張和股、元和千元）。發現的問題寫成 `known_defects` 和品質旗標，不偷偷修改原始資料。

盤點結果交給人確認之後，再定資料集。

## 2. 定資料集與欄位目錄（單一真實來源）

在一個檔案裡寫清楚每個資料集：來源表、主鍵、key 欄、日期欄、每個欄位的 `{key,label(單位),group,required,in_default_set,note}`、單位換算，以及 lineage。schema 端點、SQL 產生、匯出和文件，都要從這個目錄讀，不能各寫一份。

## 3. 品質層

把每個已知缺陷做成旗標規則。每一列都要算出 `quality_status` 和 `quality_flags`，`strict` 模式要清空哪些欄位也在這裡定義。只做標記，不改原始值。

## 4. 伺服器

- 用 Node 內建的 `http` 就好，不用框架；資料庫驅動選最少依賴的（SQL Server 用 `mssql`，PostgreSQL 用 `pg`），版本要固定，安裝前要先問人。
- 依契約實作 `doc`、`me`、`manifest`、`schema`、`extract`、keyset 分頁游標、配額、錯誤格式和稽核紀錄。
- 用唯讀交易查詢，並設逾時；`limit` 要有上限。
- `data_version` 用各表列數、最大更新時間或最大鍵值算雜湊，有任何資料進庫就會跟著變。

## 5. 文件與防漂移

- `DATA_API.md` 照範例的章節寫：先放三十秒版本，再寫「先讀這一節，否則你算出來的數字會是錯的」（缺陷、單位、容易誤用的欄位），然後是端點、分頁、配額、錯誤、完整範例（Node 不裝套件）、資料集與涵蓋範圍、硬邊界、出事找誰。
- 文件裡的欄位表和錯誤碼表要從程式產生，或用測試比對，避免文件跟程式不一致。
- 寫一支 `smoke`：真的打每個端點，驗證翻頁到最後一頁、409、429、BLOCK 列被清成 null、未知欄位回 400。

## 6. 開放方式

- 只給本機用：綁定 `127.0.0.1`。
- 給區網用：綁定網卡位址，並開防火牆規則，只開這個 port。這一步要先問人。
- 固定網址對外：範本的做法是 Cloudflare Worker 加上隧道，服務本身仍然只綁 127.0.0.1，再加邊緣封條擋掉直接連隧道的請求。這屬於對外動作，一定要先問人，而且網址就是權限。
- 開機自動啟動加看門狗：防止重複啟動要用 PID 鎖檔，不要比對命令列字串。

## 7. 首次啟用驗收

照範本的 SOP，換成另一個 AI（或一個全新的對話），只給它 `DATA_API.md` 和需求模板，讓它自己寫程式來撈。用三組數值指紋檢查：一個資料集的總列數、某欄的加總、某一筆具體值。三組都跟直接在資料庫算出來的結果一致，才算整條路是通的。

## 範本踩過的雷

- PostgreSQL 的 DATE 欄位如果不設 type parser，在 UTC+8 會整批往前平移一天。
- 代號要當字串處理（0050 不是 50）。
- 經過 Cloudflare 時，ETag 會被改成弱 ETag `W/"..."`，比對前要先把前綴拿掉。
- 主鍵含類別欄的表，同一天可能有兩筆，直接 join 會讓價格列重複，要先 group by。
- 日更要驗證「回傳資料的日期等於請求的日期」，否則會把前一天的資料蓋上今天的日期。
- 不要因為少數壞列就讓整批回 409，否則 API 會變成不能用。正確做法是清空那幾格並留下旗標。
