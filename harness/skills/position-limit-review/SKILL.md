# position-limit-review — 部位/限額檢核

檢核紀律,不是計算引擎。遵守常駐紅線 `MIDOFFICE.md`(建議單模式、超限語意;安裝後位於 `~/.claude/MIDOFFICE.md`)。研究依據:套件 `docs/midoffice-research-raw.json`(value-at-risk.net 限額分類、SEC 15c3-5、Basel FRTB、台灣證券商管理規則、兆豐證實例;僅存於套件,未隨 skill 安裝)。

## 1. 檢核矩陣(缺一維就標「資料不全」,不得只看單一指標判安全)

| 限額類型 | 性質 | 例 |
|---|---|---|
| 部位/名目 | 前瞻 | 名目金額、股數、淨值比 |
| 停損(損失)| 回顧 | 1日/1週/1月累計損失 |
| VaR | 兼具 | 99% 1-day VaR ÷ 限額 |
| 集中度 | 前瞻 | 單一發行人/產業餘額 |
| Greeks/敏感度 | 前瞻 | delta/gamma/vega/duration |

每類在**交易員 → 交易桌 → 全公司**三層各算 utilization(現值 ÷ 限額)。層級嵌套:員 ≤ 桌 ≤ 司。

## 2. 分級與動作(寫死,不因對話語氣鬆動)

- **< 80%**:正常。日報列示即可。
- **≥ 80%(或公司自訂預警線)= soft**:預警。輸出:哪個限額、utilization、驅動因子(哪些部位貢獻最多)、可行的減倉/避險選項。通知 trader 層級。
- **≥ 100% = hard breach**:只輸出超限事實 + 升級呈報草稿(桌主管→風管→總經理/董事長依公司升級路徑;異常即時、日常每日)。**不提供**「解釋掉」「先交易再補報」的任何選項。
- 每次 soft/hard 都寫入 breach register(§4)。

## 3. 台灣法定硬紅線(高於公司內規,引用時附條號)

- 證券商管理規則第 19 條:持有任一**本國**公司股份 ≤ 已發行股份 10%,持有其有價證券成本總額 ≤ 證券商淨值 20%;任一**外國**公司股份 ≤ 5%、有價證券成本總額 ≤ 淨值 20%,**其中股權性質有價證券 ≤ 淨值 10%**(同條尚有關係人、券商公司債等款次,檢核時對照全條文)。
- 資本適足率(CAR)< 150% 依級距觸發業務限制。管理規則第 31-4 條:**自行買賣外國有價證券及外國衍生品**者,CAR **連續三個月**低於規定時僅得出售或結清該等部位——此為法定義務,適用範圍與觸發條件照條文。至於「偵測到 CAR 低於門檻即全面切僅減倉模式」是本 harness 的**穩健預設(公司內規層)**,非 31-4 條要求,公司有明確政策時以政策為準。
- 限額版本要可溯源:引用限額時附版本/核定日(限額由董事會核定是台灣內控要求);SEC Rule 15c3-5 實務(FINRA 監理報告點名):限額值須有書面設定理由(rationale),缺 rationale 的限額標註為缺陷。

## 4. breach register(結構化,禁止只用自然語言轉述)

每筆:`{時間, 限額ID+版本, 層級, utilization, soft/hard, 驅動部位, 處置建議, 通知對象, 核准人, cure完成時間}`。引用歷史 breach 時引 register 條目。累積資料供 time-to-cure SLA 與年度控制有效性檢視。

## 5. 臨時調限(ad hoc)

AI 只產生申請單:`{申請人, 限額ID, 現值→請求值, 理由(必填), 時效, 到期回復條件, 核准人(必填)}`。對應 FINRA 實務:書面理由 + 自動回復(automated reversion)。**AI 永不直接改限額參數。**

## 6. 輸出格式(每次檢核)

1. 狀態行:`X 個限額檢核,soft N / hard M,距收盤/申報 cutoff 還有 T`。
2. utilization 矩陣表(只列 ≥ 預警線的 + 摘要統計,exception-based)。
3. breach 明細(register 格式)。
4. 附驗算:計算用的程式/查詢 + 資料來源與時點(lineage)。

## 為什麼這樣設計(教材)

- 層級式限額與 VaR 限額是業界主流(Fed 實證:桌級 VaR 限額是 trader 實際最在意的約束)。
- soft/hard 分離對應 SEC Rule 15c3-5(市場准入規則)的 soft block(人審放行+留紀錄)vs hard block(系統阻擋);AI 屬於「輔助人審」層,所以連 soft 放行都只能草擬、不能決定。
- exception-based 報表:全量表沒人看,異常才是資訊。
