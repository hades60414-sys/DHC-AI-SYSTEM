# risk-metrics-review — 風險指標覆核

遵守常駐紅線 `MIDOFFICE.md`(獨立性、lineage;安裝後位於 `~/.claude/MIDOFFICE.md`)。研究依據:套件 `docs/midoffice-research-raw.json`(Basel FRTB、value-at-risk.net、FRTB PLA;僅存於套件)。

## 1. 覆核的定位

覆核 ≠ 重建模型。目標是回答:**這個數字合理嗎?變動能解釋嗎?模型還可信嗎?** 三個層次各有工具:

## 2. 合理性檢查(每日可做)

- **量級**:VaR vs 部位規模與波動度的粗估(如 VaR ≈ 名目 × σ_daily × 2.33 的量級檢查,99% 1-day);差一個數量級必有事。
- **變動歸因**:今日 VaR vs 昨日——部位變了?波動率輸入變了?模型/參數變了?三者拆開;「都沒變但 VaR 跳」= 開 exception。
- **交叉一致**:VaR 方向與 Greeks 一致嗎(delta 大增但 VaR 不動 = 可疑);各桌加總 vs 公司層級(分散效果合理嗎)。
- **輸入品質**:波動率/相關性用的資料期間與時點;輸入價過 `[[data-quality-gate]]`(STALE 輸入的 VaR 標注品質狀態)。

## 3. VaR backtesting(觀念 + 覆核點)

- 99% 1-day VaR 預期每年 ~2-3 次穿透(250 交易日)。例外太多 = 模型低估;**例外太少也異常**(模型過度保守,資本效率差)。
- 每次穿透記錄:日期、實際損益 vs VaR、原因(市場跳空/新部位/模型盲點)。監理框架(Basel 交通燈)以 250 日例外數分區——綠(≤4)/黃/紅。
- 覆核點:例外是「集中在特定品種/情境」還是隨機?集中 = 模型結構性盲點。

## 4. 壓力測試覆核

- 情境是否涵蓋當前部位的**真實痛點**(不是只跑歷史情境):集中度大的地方有沒有專屬情境?
- 壓測結果 vs 停損限額/資本:最壞情境虧損落在承受範圍嗎?
- 情境參數多久沒更新(市場結構變了情境還是舊的 = 形式化)。

## 5. FO vs 風險系統一致性(進階,FRTB PLA 思路)

前台定價與風險模型對同一部位算出的 P&L 應該高度一致。可借用 PLA 的量化思路:相關性(Spearman)+ 分布距離(KS)打分,交通燈分區,做成 desk 級長期品質儀表板。持續劣化 = 兩套系統的模型/資料在漂移。

## 6. 覆核輸出格式

1. 結論行:`VaR 合理性 綠/黃/紅 + 一句依據`。
2. 檢查清單逐項:通過/異常 + 證據。
3. exception(若有):`{檢查項, 觀察值, 預期範圍, 候選原因, 建議追查}`——**覆核者提出質詢,模型 owner 負責解釋;AI 不替模型 owner 給結論**。
4. 重算/粗估的 code 附上;重算須用獨立實作,不得抄待驗證系統的公式當驗證。

## 為什麼(教材)

- 「例外太少也是異常」:backtesting 是雙尾檢定——多數新手只查低估,漏掉過度保守的資本浪費。
- 獨立重算的意義:同一套邏輯算兩遍只驗證「沒打錯字」,驗證不了模型;粗估量級反而是最強的荒謬偵測器。
- 桌級視角(FRTB):風控與監管的基本單位是 trading desk,覆核粒度到桌才有行動意義。
