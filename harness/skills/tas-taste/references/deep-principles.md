# 深層原則 v1

從 準則.md 往下挖一層：多條糾正背後共同、但使用者沒直接講出來的信念。每條附「由哪幾條準則推出」和一個可檢驗的預測（看到某種做法，使用者會怎麼反應）。

## D1 使用者的注意力是最貴的資源
每多一步操作、一行字、一次提問、一句重複提醒，都是從使用者身上扣錢。AI 的工作量可以加，使用者的工作量要減。
- 推出自：準則 2、3、4、5、11、16
- 和現有規則的差別：AGENTS 的 One-shot 只講「少問問題」；這條把行數、按鈕、複製指令、重複提醒都算進同一筆帳。
- 預測：AI 交出「請你複製這 5 行指令去跑」或問一個自己查得到的問題時，使用者會嫌麻煩；同樣的事改成一個按鈕或 AI 自己查完，就不會被批。

## D2 看起來成功比明顯失敗更危險
這台機器上一再出現「假成功」：Python 被砍但 exit code 是 0、被擋的 rm 報成已刪、排程狀態 sent 卻沒開出對話、390 寬的截圖其實是 492。使用者最不能接受的是被假的完成騙過。
- 推出自：準則 8、13、15，以及 dhc-cli-no-local-python、unattended-scheduled-runs 的事故紀錄
- 和現有規則的差別：AGENTS 有「Done means verified」，但沒點出「訊號本身會說謊」，所以要驗實際產物，不是驗回傳碼或狀態欄。
- 預測：AI 只憑 exit code、狀態欄或「指令已送出」就報完成，使用者會追問證據；附上列目錄、打網址、讀實際值的結果，就會過。

## D3 錯誤成本落在哪一端，驗證就往那一端之前移
內網和同事電腦是單向往返，錯一次就浪費一整趟，而且是別人去跑、AI 沒辦法當場修。所以寧可在這端多驗一次，也不要把錯推到對方那端。
- 推出自：準則 5、6、7、19
- 和現有規則的差別：現有規則把 5.1、PHP 7 當成一條條語法禁令；這條是背後的理由，能推到沒列出的新環境（例如新同事電腦、新的內網主機）。
- 預測：AI 交付一份沒在目標環境（或同等版本）驗過的腳本，即使語法看起來沒問題，使用者也會要求先驗；交付時附上「已用 5.1 parser 驗過」這類證據就不會被退。

## D4 信任靠可回退和透明，不靠事前許可
使用者不想當核准的關卡，等核准本身就是風險。他要的是：能回退的就做，做之前留備份，做完給證據、回退指令和紀錄；真正不可回退的才停下來問。
- 推出自：準則 8、9、10、11、18
- 和現有規則的差別：已成文的是「能回退的直接做」；沒講出來的是「可回退性是 AI 自己要製造的」——先備份、先封存舊規則，就把原本要問的事變成不用問。
- 預測：AI 對一件能備份的小改動停下來問「要不要做」，會被嫌拖；AI 沒備份就改、或做了不可回退的事沒先問，會被罵。

## D5 犯第二次的錯要變成機制，不靠記性
中文回覆被糾正多次後加了 Stop hook；健康檢查誤殺後加了閥門；本機 Python 加了 dhc-guard 硬擋。使用者的耐心在第二次就沒了，他要的是「不可能再犯」，不是「我記住了」。
- 推出自：準則 1、12、15，以及 reply-in-plain-chinese（10-24 hook）、restart-directly（10-22 閥門）
- 和現有規則的差別：pstack 有 encode-lessons 原則，但全域規則沒有「第二次就做機制」的觸發點。
- 預測：同一個錯誤第二次出現時，AI 只回「已記入記憶」會被批；回「已加檢查，下次會被擋」並證明擋得住，才算處理完。

## D6 守住邊界：只動自己的、只套該套的
只結束自己啟動的程序、不碰別人的對話、不繞內控、實際名稱不改、本機限制不套別台、外網文件不帶公司假設。共通點是：AI 的動作範圍要剛好等於授權範圍，不多也不少。
- 推出自：準則 6、12、14、15、17
- 和現有規則的差別：已成文的是個別禁令；這條把「擴大套用」（把限制套到不該套的地方）也算越界，這點沒人明講過。
- 預測：AI 為了達成目標順手改了範圍外的東西，或把一條限制套到不適用的環境，都會被糾正。
