# Installation Guide

> English translation of [安裝說明.md](安裝說明.md). The Chinese original is authoritative. Terminology: [docs/GLOSSARY.md](docs/GLOSSARY.md).

> Don't want to read this yourself? Open Claude Code in the repo folder and paste the whole of [SETUP_PROMPT.en.md](SETUP_PROMPT.en.md). The AI will ask about your use case first and then walk you through the installation step by step.

**Three things up front**

1. **Every step can be undone.** Old files that get overwritten are backed up automatically; if you no longer want it, run step 6 to go back to how things were.
2. **You don't have to install everything.** If you only want to try one or two skills, see the beginning of [SKILLS.md](SKILLS.md): copy one folder and it works, without touching your existing setup at all.
3. **Most people only need steps 1 and 2.** Step 3 onward is for people who run the host or want to study the architecture.

| Step | For whom | What it changes on your computer | How to undo |
|---|---|---|---|
| 1 Rules and skills | People who want the whole way of working | `CLAUDE.md`, `AGENTS.md`, `MIDOFFICE.md`, `pstack-models.md`, `skills\`, `agents\` in `%USERPROFILE%\.claude\` | Step 6 |
| 2 Safety guardrails | Recommended for everyone | Four files in `.claude\hooks\`, the hooks section of `settings.json` | Step 6 |
| 3 Other components | People who run the host or study the architecture | Depends on the component | Depends on the component |

## 0. Prerequisites

| Item | How to check | If you don't have it |
|---|---|---|
| Windows 10 / 11 | — | The scripts are mainly for Windows; on Mac / Linux you can only borrow the skills and rules (copy the folders) |
| Node.js 22 or later | Type `node --version` in Command Prompt | Install the LTS version from [nodejs.org](https://nodejs.org/) |
| Git | `git --version` | Install from [git-scm.com](https://git-scm.com/); or on the GitHub page click Code → Download ZIP and unzip it |
| Claude Code | `claude --version`; the first time, type `claude` to log in | Install following the [official instructions](https://docs.anthropic.com/en/docs/claude-code) |

Download the repo (the URL is under the green Code button at the top right of the GitHub page):

```
git clone <repo URL> C:\tas
```

The `powershell -NoProfile -ExecutionPolicy Bypass -File ...` used below means "allow this script to run this one time only"; it does not change your computer's security settings.

## 1. Rules, skills, subagents

**First decide whether to change the rules.** `harness\rules\` contains the working habits of a middle-office team at a securities firm: reply in Traditional Chinese, lead with the conclusion, ask first about any logic that computes money, and have important deliverables independently verified. The general direction applies broadly, but a few parts only fit the original team (see the last section of [harness/README.md](harness/README.md)).

> 💡 Not sure what to change? Ask Claude Code: "Read CLAUDE.md, AGENTS.md and MIDOFFICE.md in harness\rules and show me the rules that only apply to the securities firm's middle office."

> Translator's note: the rules ask the AI to reply in Traditional Chinese. If you want English replies, edit the `Communication` section of `harness\rules\CLAUDE.md` before syncing, and add `--no-zh` in step 2.

Once you have changed them (or decided not to):

```
cd C:\tas\harness
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\sync-harness.ps1 -Target Claude -Check
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\sync-harness.ps1 -Target Claude
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\healthcheck.ps1
```

- The first line only lists which files would be added or overwritten and changes nothing; run the second line once that looks fine.
- Old files that get overwritten are backed up to `%USERPROFILE%\.claude\backups\harness-sync-<timestamp>\`.
- You're done when the third line ends with `RESULT: OK`. New Claude Code sessions load it automatically.
- If you also use Codex: change `-Target Claude` to `-Target All` in all three lines (add `-Target All` to healthcheck as well).
- If Ollama isn't installed locally you only get an INFO line; it does not affect the result.

To change the rules later: edit the copy in `C:\tas\harness\rules\` and run the second line again. Settings that belong only to this computer go in `%USERPROFILE%\.claude\CLAUDE.local.md`, which syncing never overwrites.

## 2. Safety guardrails

```
cd C:\tas\harness
node ops\install-hooks.cjs --check
node ops\install-hooks.cjs --guard
```

The first line is only a preview; the second backs up `settings.json` and then **adds** the following (your existing hooks are kept):

| Guardrail | What it does |
|---|---|
| `secret-guard` | Blocks outgoing content that contains what looks like a key, a national ID number or a credit card number; only warns for emails and mobile numbers |
| `egress-log` | Records every outbound data transfer in `%USERPROFILE%\.claude\egress-log\`; does not block, so you can review afterwards |
| `build-check` | When you are about to build a new skill, hook or plugin, reminds you to look for an existing one first; does not block |
| `zh-reply-guard` | If the body of a reply is in English, asks the AI to rewrite it in Traditional Chinese; add `--no-zh` if you don't want this |
| `dhc-guard` (`--guard`) | Stops dangerous commands such as `rm -r`, force push, `git reset --hard`, `DROP`, and `DELETE` without WHERE; they run once only after you reply `確認執行` ("confirm execution", type these Chinese characters exactly); requires Claude Code 2.1.287 or later |

**Try it out:** open a new session and ask it to "use Bash to print `sk-ant-` followed by 30 x's". You should see a message saying secret-guard blocked it (this is a fake key, so it's safe). Then ask it to "use Bash to run `rm -r C:/Temp/tas-guard-test`" (it doesn't matter if the folder doesn't exist); dhc-guard should stop and wait for you to reply `確認執行`. At that point, just reply "no".

## 3. Other components (as needed)

These are not required for using the rules and skills. Most need extra machines or accounts and have the original environment's paths hard-coded, so treat them as reference implementations:

| What you want to do | Where to look | Also needed | Difficulty |
|---|---|---|---|
| Services around web Claude Code: de-identifying model proxy, auto-resume after hitting usage limits, health checks | `web-ops\` (`cc-hosts\` holds the scheduled operations scripts), [ARCHITECTURE.md](ARCHITECTURE.md) | DHC CLI (separate repo); a Cloudflare account for a public URL | Medium |
| Safely send commands to intranet machines from outside | [remote-agent/README.md](remote-agent/README.md) | .NET Framework 4.x on the intranet machine, HTTPS storage reachable by both sides, certificates you generate yourself | High |
| Offline local model | [local-model/DELIVERY.md](local-model/DELIVERY.md) | A machine with a GPU, llama.cpp and a model (change the download source yourself) | Medium |
| Action gate, local document Q&A, reminders, skill usage statistics, project memory template | README in each `tools\` folder | Node 22 | Low |
| Host migration | Header comment of each file in `migration\` | Cloudflare account | High |

## 4. Adapting it to your environment

These are placeholders in the repo; replace them with real values before using the components in step 3:

| Placeholder | Meaning |
|---|---|
| `D:\TAS\...`, `C:\Users\demo\...` | Install path and account of the original environment |
| `srv-main`, `srv-db`, `srv-rag`, `srv-src`, `srv-nas`, `srv-old`, `srv-db2`, `pc-mgr` | Host roles: control host, database host, local-model host, source database, file server, old host, second database, manager's PC |
| `10.255.0.x` | Fake IP |
| `DHC`, `EKB`, `RAG1`, `ragent` | Company CLI name, enterprise knowledge base, local-model host, remote agent |
| `TRADE_DB`, `TRADE_DB_TEST` | Production and test databases |
| `userA`–`userG`, "Colleague A"–"Colleague G" (同事A–同事G) | Team members |
| `<worker>.<account>.workers.dev`, `__KV_ID__` | Cloudflare Worker URL and KV ID |

To find what needs replacing: `git grep -n -e "D:\\\\TAS" -e "srv-" -e "10\.255\.0\."`.

## 5. Known issues

- Two tests in `web-ops\assistant-guard.test.cjs` assume the home directory is `C:\Users\demo` and fail under other accounts.
- `tools\action_gate\test_matching.cjs` needs an experiment data file from the original environment that is not in the repo, so it fails.
- `company-environment` and `company-intranet` are fill-in-the-blank templates: the originals contain internal company information and were not included. These versions are only useful once you replace `<...>` with your own environment (see [SKILLS.md](SKILLS.md)).
- `video-studio` ships only the offline Windows built-in voices (Yating, etc.); the Edge online read-aloud the original team used has no public license and was not included. For a more natural voice, connect Azure AI Speech yourself (requires a key).

## 6. Uninstall

```
cd C:\tas\harness
node ops\install-hooks.cjs --remove
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\uninstall-harness.ps1 -Check
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\uninstall-harness.ps1
```

- The first line removes the guardrails from `settings.json` (after backing it up). The four files in `.claude\hooks\` are harmless if left; delete them yourself if you don't want them.
- The last two lines delete no files: the rules, skills and subagents this package installed are moved to `%USERPROFILE%\.claude\backups\harness-uninstall-<timestamp>\`, and the original files overwritten during the first install are put back. Skills you installed separately are not affected.
- The `CLAUDE.local.md` created during installation is a blank template and harmless to keep.

## 7. Before sharing files you have changed

```
node scripts\scan-sensitive.mjs
```

Share only when it prints `clean`. Put your own organisation's proprietary terms in a JSON file outside the repo and point the environment variable `SCAN_SENSITIVE_TERMS` at it (format in `scripts\scan-sensitive.example.json`).
