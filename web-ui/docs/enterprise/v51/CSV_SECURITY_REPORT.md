# RG-V5-02｜CSV 公式注入（V5.1）

## 可達性追查

`buildReconciliationExport()` 的所有欄位都來自已存的 ACC-MATCH-v1 結果：

| 欄位 | 來源 | 可否攜帶任意字串 |
|---|---|---|
| 規則版本、匯出版本、對帳 ID、結果 hash、期間 | 伺服器產生或已驗證 | 否 |
| 完成結果：案件 ID、單據 ID、內部帳／收款列 ID、客戶代碼 | 通過 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` | 否（不能以 = + - @ 開頭） |
| 完成結果：分類、原因、幣別 | 固定代碼／白名單 | 否 |
| 完成結果：金額、差額、行號 | 整數（差額可為負，例 `-5000`） | 只能是整數 |
| **拒收結果：`errors[].rowId`** | **原始 CSV 儲存格**（`COLUMN_COUNT` 取 `cells[0]`；`INVALID_資料列ID` 保留未通過驗證的原值） | **是：任意字串可達匯出** |

結論：存在可達路徑。合法的 ACC-MATCH 請求（一份格式錯誤的內部帳）即可讓 `-1+1`、`＝1+1` 等值出現在拒收結果的 CSV 匯出中。

## 修正

`neutralizeCsvCell`：純整數（`^-?\d+$`）原樣保留；其他值去除前導空白（含全形空白）後，以 `= + - @`、全形 `＝ ＋ － ＠`、U+2212、U+FE63 開頭，或以 Tab／CR 開頭 → 前置單引號。所有欄位一律加引號。V5 的防護在「`-` 後接數字」時放行，所以 `-1+1`、`-2*3` 未被中和（RED）。

## 驗證

| 層級 | 內容 | 結果 |
|---|---|---|
| 回歸測試 | 9 個 payload 經真實 ACC-MATCH 拒收路徑抵達匯出，逐一確認中和；`-5000`、行號不變 | PASS |
| 試算表實測（CI `csv-spreadsheet-safety`） | LibreOffice Calc 24.2 無頭匯入，**開啟「求值公式」**，比對顯示值；對照組不加防護 | guarded 12/12 未被求值 |
| 對照組觀察 | LibreOffice 只把 `=` 開頭的值當公式（`=1+1`→`2`、`=HYPERLINK`→`x`）；`+ - @` 與全形字元在 LibreOffice 不求值 | 2/12 被求值 |
| Microsoft Excel | GitHub Linux runner 無法執行 | **NOT_RUN** |

因此：對 `=` 開頭的值，實測證明防護有效；對 `+ - @` 開頭的值，LibreOffice 本身不求值，防護在 Excel 的效果**沒有實測**，依 OWASP CSV Injection 建議保守中和。
