> 2026-10-29：本分支新版image／Compose migrator已完成本機Linux ARM64合成驗收（PG12、restore9表、容器工作台5組／persist／safeDown），raw logs在evidence/PREV3_20261029。原文「尚未驗image」是歷史，當前已補驗；企業RBAC／正式Cloudflare／客戶部署仍未完成，安裝前仍需原capacity guard。

這是 CloudCLI UI (https://github.com/siteboon/claudecodeui) 的 DHC CLI 衍生版本。保留根目錄 LICENSE／NOTICE 與上游署名。E02a 已加入獨立 PostgreSQL 內部資料層，企業 Auth／RBAC 仍未完成，不提供多人對外服務。本輪只用合成資料驗收。

## 安裝

需要 Docker Engine + Compose；macOS 可用 Docker Desktop，或本輪採用的 Colima。可用 `docker-compose` standalone，無需修改使用者 Docker 設定。

```bash
# 從 repo 根目錄執行；Colima 使用專用 profile，沒有登入常駐。
python3 scripts/enterprise/檢查測試容量.py --stage before-vm && colima start --profile dhc-enterprise-qa --cpu 2 --memory 4 --disk 20 --vm-type vz --runtime docker --activate=false
export DOCKER_HOST="unix://${HOME}/.colima/dhc-enterprise-qa/docker.sock"
# Homebrew Compose 的獨立入口；不寫 ~/.docker/config.json。
export COMPOSE_PROJECT_NAME=dhc-local
export DHC_SOURCE_SHA="$(git rev-parse HEAD)"
python3 deploy/customer-single/產生本機資料庫密碼.py
docker-compose -f deploy/customer-single/compose.yaml config --quiet
docker-compose -f deploy/customer-single/compose.yaml build
docker-compose -f deploy/customer-single/compose.yaml up -d --wait db
docker-compose -f deploy/customer-single/compose.yaml --profile tools run --rm migrate
docker-compose -f deploy/customer-single/compose.yaml up -d --wait app
```

每個客戶須使用不同 COMPOSE_PROJECT_NAME，讓 network／volume 完全分開。

首次打開 `http://127.0.0.1:3001` 用原 DHC 表單設帳號。`.env.example` 只有非秘密設定與密碼目錄位置，沒有密鑰；產生器寫入 gitignored `.secrets/` 三份 0600 env 檔，重跑不換密碼；如要使用 `.env` 請自行複製到 compose 同目錄，勿覆蓋既有檔案。原個人與 Agent 入口保留；實際 Provider 登入／模型請求需獨立授權，本片未驗收。不要掛主機家目錄或 Docker socket。

## 真實驗收

```bash
node --test deploy/customer-single/healthcheck.test.mjs
# 需 Python Playwright 與 Chromium；本機驗收用已安裝的 Chromium 1248。
# 若本機只有 Homebrew Compose，建立暫存 Docker config 的 cliPluginsExtraDirs：
# /opt/homebrew/lib/docker/cli-plugins，再以 DOCKER_CONFIG 指向它。
mkdir -p .tmp/docker-client
python3 - <<'PYCONFIG'
import json
from pathlib import Path
Path('.tmp/docker-client/config.json').write_text(json.dumps({
    'cliPluginsExtraDirs':['/opt/homebrew/lib/docker/cli-plugins']
}))
PYCONFIG
DOCKER_CONFIG="$PWD/.tmp/docker-client" python3 tests/enterprise/容器驗收.py
python3 - <<'PYCLEAN'
import shutil
shutil.rmtree('.tmp/docker-client')
PYCLEAN
```

驗收器建立隨機 `dhc-e01-*` project、未使用 port、合成帳號與 volume；驗證原 UI 登入、401/403、Codex session 建立、WS 回應、health 失敗和 down/up 持久化。finally 只刪該 QA project 的合成 volume，關閉瀏覽器。一般安裝不執行 `down --volumes`。

## 停止、重啟、回退

```bash
# 保留 dhc-state volume，不會清除帳號/個人設定/session。
docker-compose -f deploy/customer-single/compose.yaml down
docker-compose -f deploy/customer-single/compose.yaml up -d --no-build --wait
# 原始碼回退：git revert <E01完整commit SHA>，見 CODEX_RUN_REPORT。
# image 回退：設定 DHC_IMAGE 為上一個驗收 image，再 up -d --no-build。
# 本輪 QA 結束後停止專用 VM，不建立 brew services/launchd：
colima stop --profile dhc-enterprise-qa
```

E01 沒有 migration；E02a 的 enterprise-pg 與原 dhc-state 為不同 named volumes，既有主機 SQLite 完全不掛入。正式資料的 volume 不可刪除。PG migration、備份還原與破壞性 Down 警告見 [Migration 操作](../../docs/enterprise/MIGRATIONS.md)。原 SQLite volume 的備份還原仍是後續項目。

## 實作限制

- health 只檢查 `/health` HTTP 200 與 status ok；不是 DB readiness／模型健康。
- base image 固定 manifest digest，npm 使用原 lock。Build metadata 記來源 SHA；dirty snapshot 的 patch 指紋需與 evidence 同存。
- 原 team、全域 API、shell 與 plugin 仍屬單使用者信任邊界。容器限制無法替代資源 policy／audit；不得開放外網或向企業員工宣稱 RBAC 已完成。
- E02a PostgreSQL migration、最低權限帳號、scope、dump/restore 已以合成資料實測；enterprise RBAC／session 撤權仍 PENDING。
- 新版完整 app image 與 Compose migrate service 尚未重建驗收（磁碟空間不足）；上列 build/run 為可執行補驗指令，不代表已通過。E01 舊 image 證據不能套用到 E02a。
- 不啟用 Cloudflare、R2、不使用銀行或客戶資料；正式原始碼提供／IP／品牌清單需在發佈 Gate 再審。


## shared-r2 容量 preflight

啟動專用 VM 前先跑 `python3 scripts/enterprise/檢查測試容量.py --stage before-vm`。exit 0 才繼續；exit 3/PENDING_ENV 表示可用空間低於12GiB保守預算，exit 2表示無法取得容量。這是預算而非測得峰值，也不保證後續不因其他程序耗空磁碟。不要在非0結果後繼續其餘安裝指令。

兩個 QA runner 另在建立 evidence/秘密/容器前執行 running-vm 檢查（至少2GiB餘量）；不足直接停止，不嘗試刪任何資料、重設權限或隱藏失敗。若 VM 是由操作者先啟動，preflight 不擅自關閉它；只在確認為自己的合成QA profile後執行對應 cleanup。`--resume-state`被容量拒絕時不碰既有state/volume，先按交接紀錄安全收尾。

容量工具可獨立測試：`python3 -m unittest discover -s tests/enterprise -p test_capacity_preflight.py`。當容量尚不足，PG/image/scoped pagination仍PENDING，不能由容量單元測試替代資料庫驗收。
